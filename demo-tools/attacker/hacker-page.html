Attacks

Fire these on cue. The verdict is what the audience should read off the victim's live feed.

1 · Take over the account

One button, fired exactly the same way every time: the victim's cookie, from here, with no proof. Whether it works is decided by the victim's session, not by us — press it before and after they enable PulseLock and read the real result.

2 · Tamper a signed request

Keep the victim's real signature, rewrite the amount, resend → body_hash_mismatch.

3 · Replay verbatim

Resend the captured proof completely unchanged → single-use nonce already spent → nonce_reused.

4 · Replay the same captured request, on cue

One button, fired exactly the same way every time — like Attack 1. Press it while the victim's session is still live and the genuinely-captured request goes through for real. Have them press "Revoke this session" on their page, then press this again → the session itself is dead → session_inactive, checked before the signature even runs.

5 · Forge a signature with a new key

Build a fresh, real nonce and a correct origin/path/body_hash for the stolen session — then sign it with a brand-new key pair generated right here, never the victim's browser → signature_invalid.

6 · Replay from a different origin

Resend the captured proof completely unchanged, but from a different origin than it was actually signed for → the signature still verifies, but the asserted origin no longer matches → request_mismatch.
